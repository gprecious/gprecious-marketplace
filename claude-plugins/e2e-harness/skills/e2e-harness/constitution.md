# harness-engineering 헌법

모든 레시피가 준수한다. (출처: research/2026-06-17-ai-agent-playwright-e2e-test-harness)

1. **크리티컬 플로우만** — 실패 시 매출/데이터/신뢰가 깨지는 곳. 사람이 선택한다.
2. **통제 가능한 것만** — 외부 의존성은 호출 위치별 모킹: 브라우저 직접 = 인터셉트(page.route),
   서버/SSR/BFF = 환경변수 고정 응답. 통제 불가 외부 서비스는 테스트하지 않는다.
3. **결정론적 상태 시딩** — 테스트용 API/시드로 멱등 주입, teardown 으로 복원.
4. **플래키는 작성 단계에서** — 시맨틱 셀렉터, 조건 기반 대기(고정 sleep 금지), 머지 전 번인.
5. **에이전트 heal 루프** — 실패는 trace/아티팩트로 진단·자가수정. 사람은 루프 설계·도메인
   맥락 제공·하네스 갱신을 맡는다.
